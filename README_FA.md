# سودیار (بخش ۱ – فقط خواندن)

این برنامه فقط **اطلاعات کالاهای خودتان** را از پنل فروشنده دیجی‌کالا **می‌خواند** و در پایگاه داده ذخیره می‌کند.
**هیچ چیزی در دیجی‌کالا تغییر نمی‌کند** (نه قیمت، نه موجودی، نه تخفیف).

## قبل از شروع (فقط یک بار)
1. برنامه **Docker Desktop** را نصب کنید و باز کنید (از docker.com). صبر کنید تا آماده شود.
2. توکن شخصی (Self Token) را از پنل فروشنده دیجی‌کالا بردارید.
3. این پوشه را روی کامپیوتر خود دانلود کنید.

## مرحله ۱: ساختن فایل رمزها
1. در پوشه برنامه، فایل `.env.example` را پیدا کنید.
2. از آن یک کپی بگیرید و اسم کپی را بگذارید `.env` (دقیقاً همین، با نقطه اول).
3. فایل `.env` را با Notepad باز کنید.
4. جلوی `DIGIKALA_SELF_TOKEN=` توکن خود را بچسبانید (بدون فاصله و بدون گیومه).
5. جلوی `POSTGRES_PASSWORD=` یک رمز دلخواه بنویسید (مثلاً یک جمله طولانی بدون فاصله).
6. بقیه خط‌ها (آدرس دیجی‌کالا و غیره) از قبل درست پر شده‌اند؛ به آن‌ها دست نزنید.
7. فایل را ذخیره کنید و ببندید.

⚠️ فایل `.env` را برای هیچ‌کس نفرستید و در اینترنت نگذارید.

## مرحله ۲: روشن کردن برنامه
1. داخل پوشه برنامه، روی فضای خالی کلیک راست کنید و «Open in Terminal» (باز کردن ترمینال) را بزنید.
2. این را بنویسید و Enter بزنید:

```bash
docker compose up -d --build
```

3. چند دقیقه صبر کنید تا تمام شود.

## مرحله ۳: بررسی تنظیمات
```bash
docker compose exec worker python -m sudyar check-config
```
اگر نوشت `Configuration OK` یعنی همه چیز درست است. اگر مشکلی باشد، به فارسی/انگلیسی ساده می‌گوید چه چیزی کم است؛ فایل `.env` را درست کنید و دوباره مرحله ۲ را انجام دهید.

## مرحله ۴: خواندن کالاها
```bash
docker compose exec worker python -m sudyar sync-variants
```
در پایان تعداد کالاهای خوانده‌شده نوشته می‌شود، مثلاً: `Variants read: 120`.
هر بار که این کار را انجام دهید، یک «عکس لحظه‌ای» از قیمت و وضعیت هر کالا ذخیره می‌شود تا بعداً تاریخچه داشته باشید. چیزی پاک نمی‌شود.

## مرحله ۵: دیدن وضعیت «باکس خرید» (Buy Box)
```bash
docker compose exec worker python -m sudyar buybox-status
```
این دستور اطلاعات آخرین خواندن را نشان می‌دهد (به دیجی‌کالا درخواست نمی‌فرستد):
- تعداد کل کالاها
- در چند کالا ما برنده باکس خرید هستیم
- در چند کالا برنده نیستیم
- چند کالا در «رقابت باکس خرید» هستند

## مرحله ۶ (اختیاری): قیمت پیشنهادی برای برنده شدن
```bash
docker compose exec worker python -m sudyar winning-price 12345
```
به‌جای `12345` شماره تنوع (product_variant_id) کالا را بنویسید. فقط برای یک کالا جواب می‌دهد و فقط می‌خواند؛ قیمتی را تغییر نمی‌دهد.

## نکته مهم درباره قیمت‌ها
قیمت‌ها **دقیقاً همان‌طور که دیجی‌کالا می‌دهد** ذخیره می‌شوند و عوض نمی‌شوند. هنوز مطمئن نیستیم واحد آن ریال است یا تومان؛ بعد از اولین اجرای واقعی با قیمت‌های پنل خودتان مقایسه کنید.

## خاموش کردن
```bash
docker compose down
```
اطلاعات شما پاک نمی‌شود.

## اگر خطا دیدید
- «توکن خالی است»: مرحله ۱ را دوباره بررسی کنید.
- «Too many 429»: دیجی‌کالا گفته کمی صبر کنید. برنامه خودش ۵ دقیقه صبر می‌کند و ادامه می‌دهد.
- پیام خطا را (بدون توکن!) برای برنامه‌نویس بفرستید.

# بخش ۲: رادار باکس خرید و هشدار

رادار مرتب کالاهای شما را می‌خواند، با دفعه قبل مقایسه می‌کند و اگر چیزی عوض شد (مثلاً باکس خرید را از دست دادید) یک «رویداد» ثبت می‌کند و در صورت تمایل پیام می‌فرستد.
**رادار فقط می‌خواند و هیچ چیزی در دیجی‌کالا تغییر نمی‌دهد.**

## رویدادهایی که ثبت می‌شوند
- از دست دادن باکس خرید / پس گرفتن آن
- ورود به رقابت باکس خرید / خروج از آن
- تغییر قیمت
- تمام شدن موجودی / برگشتن موجودی
- غیرفعال شدن کالا

## علت از دست دادن باکس خرید
رادار فقط از اطلاعاتی که واقعاً دارد حدس می‌زند: «موجودی تمام شده»، «کالا غیرفعال است»، «قیمت ما از قیمت باکس خرید بالاتر است» (با درصد و مقدار فاصله). اگر هیچ‌کدام نبود می‌نویسد «نامشخص». رادار درباره ارسال، امتیاز یا عملکرد فروشنده **حدس نمی‌زند**.

## مرحله ۱: یک بار امتحان کنید
```bash
docker compose exec worker python -m sudyar radar-once
```
دفعه اول فقط وضعیت فعلی را ذخیره می‌کند و رویدادی نمی‌بینید. دفعه‌های بعد تغییرها را نشان می‌دهد. در پایان تعداد کالاها در هر گروه را می‌بینید.

## مرحله ۲: روشن کردن رادار دائمی
رادار به‌صورت پیش‌فرض **خاموش** است. برای روشن کردن:
```bash
docker compose --profile radar up -d --build
```
برای خاموش کردن:
```bash
docker compose --profile radar stop radar
```

## گروه‌بندی کالاها (هر چه مهم‌تر، بیشتر چک می‌شود)
| گروه | چه کالاهایی | هر چند وقت |
|---|---|---|
| داغ (HOT) | در رقابت باکس خرید، یا در یک ساعت گذشته باکس را از دست داده، یا خودتان «داغ» کرده‌اید | ۲ دقیقه |
| گرم (WARM) | باکس خرید را ندارند، یا در ۲۴ ساعت گذشته تغییری داشته‌اند | ۱۰ دقیقه |
| آرام (CALM) | بقیه | ۶۰ دقیقه |

گروه‌بندی خودکار است. زمان‌ها در فایل `.env` (بخش RADAR) قابل تغییرند.

## سقف مصرف
رادار فقط **۶۰٪** از سهمیه خواندن (۳۰ درخواست در ۳۰ ثانیه) را مصرف می‌کند، یعنی حداکثر **۳۶ درخواست در دقیقه**.
برآورد درخواست در دقیقه (کمترین – بیشترین؛ عدد واقعی معمولاً کمتر است چون هر صفحه چند کالا دارد):

| | داغ | گرم | آرام | جمع (بیشترین) |
|---|---|---|---|---|
| ۵۰۰ کالا (۵ داغ، ۴۰ گرم) | ۰٫۵ – ۲٫۵ | ۰٫۱ – ۱٫۰ | ۰٫۲ | حدود ۳٫۷ |
| ۵۰۰۰ کالا (۲۰ داغ، ۳۰۰ گرم) | ۰٫۵ – ۱۰ | ۰٫۶ – ۱۰ | ۱٫۶ – ۱٫۷ | حدود ۲۱٫۷ |

این‌ها برآورد هستند، نه اندازه‌گیری واقعی. بعد از اولین اجرای واقعی، با `radar-once` عدد دقیق را ببینید.

## هشدار تلگرام یا بله
هشدار به‌صورت پیش‌فرض **آزمایشی (DRY-RUN)** است: پیام فقط روی صفحه چاپ می‌شود و جایی فرستاده نمی‌شود.

برای فرستادن واقعی:
1. در فایل `.env` مقدار `TELEGRAM_BOT_TOKEN=` را (از BotFather) و `TELEGRAM_CHAT_ID=` را بنویسید.
2. برای «بله» به‌جای آن `NOTIFY_CHANNELS=bale` و مقدارهای `BALE_BOT_TOKEN=` و `BALE_CHAT_ID=` و `BALE_API_BASE=` را پر کنید (آدرس بله را باید از مستندات رسمی بله بگیرید؛ هنوز تأیید نشده).
3. بعد از دیدن چند پیام آزمایشی که درست بودند، `NOTIFY_ENABLED=true` را بنویسید.
4. رادار را دوباره روشن کنید (مرحله ۲).

نکته‌ها:
- برای هر کالا، در هر ۳۰ دقیقه حداکثر یک پیام می‌آید (`NOTIFY_COOLDOWN_SECONDS`).
- ساعت سکوت: مثلاً `NOTIFY_QUIET_START=23:00` و `NOTIFY_QUIET_END=08:00`. پیام‌های این ساعت‌ها فرستاده نمی‌شوند (به بعد موکول نمی‌شوند).
- توکن‌ها هرگز در لاگ نوشته نمی‌شوند و فایل `.env` را برای کسی نفرستید.
- قیمت‌ها همان‌طور که دیجی‌کالا می‌دهد نمایش داده می‌شوند؛ واحد (ریال یا تومان) هنوز تأیید نشده است.

# بخش ۳: کف قیمت (حداقل قیمتِ سودآور) و آماده‌سازی نهایی داکر

**این بخش فقط پیشنهاد می‌دهد. هیچ قیمتی را در دیجی‌کالا تغییر نمی‌دهد.**

## کف قیمت یعنی چه؟
کمترین قیمتی که با آن هنوز سود دلخواه شما را دارید:
`سود = قیمت − (قیمت خرید + کمیسیون + هزینه پردازش/ارسال + مالیات + سهم تبلیغات + ذخیره مرجوعی + بسته‌بندی)`

برنامه **هیچ عددی را حدس نمی‌زند**:
- کمیسیون از خود دیجی‌کالا (فقط خواندن) می‌آید؛ بخش ۳ب را ببینید. تا وقتی `sync-fees` را اجرا نکرده‌اید، وضعیت «needs_fees» است و کفی محاسبه نمی‌شود.
- اگر قیمت خرید یک کالا را ندارید: اگر «کف دستی» برایش گذاشته‌اید همان استفاده می‌شود، وگرنه وضعیت «needs_cost» می‌شود و برای آن کالا هیچ پیشنهادی داده نمی‌شود.
- قیمت‌های دیجی‌کالا ریال هستند (`DIGIKALA_PRICE_UNIT=rial`)؛ برنامه آن‌ها را به تومان تبدیل می‌کند.
- پردازش/ارسال، مالیات، سهم تبلیغات، ذخیره مرجوعی و بسته‌بندی را خودتان با دستور `set-floor` می‌نویسید (بخش ۳ب). ننوشته باشید یعنی «اعمال نشود» و گزارش این را صریح می‌گوید.

## مرحله ۱: داکر روی ویندوز (یک بار)
1. **Docker Desktop** را نصب و باز کنید و صبر کنید تا آماده شود.
2. پوشه برنامه را باز کنید. فایل `.env.example` را کپی کنید و اسم کپی را بگذارید `.env`، سپس با Notepad توکن و رمز را بنویسید (مثل بخش‌های قبل).
3. روی فایل **`1-start.bat`** دو بار کلیک کنید. بار اول چند دقیقه طول می‌کشد.

بقیه کارها هم با دو بار کلیک روی فایل‌های همین پوشه:
| فایل | کار |
|---|---|
| `2-sync.bat` | خواندن کالاها از دیجی‌کالا |
| `2b-sync-fees-sales.bat` | خواندن کمیسیون‌ها و آمار فروش از دیجی‌کالا |
| `3-radar-once.bat` | یک بار اجرای رادار |
| `4-import-costs.bat` | وارد کردن قیمت خرید از اکسل (اختیاری) |
| `5-floor-report.bat` | گزارش کف قیمت |
| `6-radar-on.bat` | روشن کردن رادار دائمی |
| `7-stop.bat` | خاموش کردن |
| `8-web.bat` | باز کردن صفحه‌ی وب سودیار (بخش ۴الف) |

## مرحله ۲: وارد کردن قیمت خرید (اختیاری)
برنامه بدون این مرحله هم کامل کار می‌کند؛ فقط کالاهای بدون قیمت خرید «needs_cost» می‌مانند.
1. یک فایل اکسل (`.xlsx`) یا `.csv` بسازید با دو ستون: **`variant_id`** (یا `sku`) و **`buy_cost`** (قیمت خرید به تومان، عدد کامل).
2. فایل را داخل پوشه **`data`** (کنار همین فایل‌ها) بگذارید.
3. روی `4-import-costs.bat` دو بار کلیک کنید، نام فایل را بنویسید. اول یک «اجرای آزمایشی» می‌بینید (چیزی ذخیره نمی‌شود) و ردیف‌های ایراددار با شماره ردیف و دلیل چاپ می‌شوند. اگر درست بود بنویسید `YES`.
4. چند بار اجرا کردن همان فایل مشکلی ندارد (چیزی تکراری ثبت نمی‌شود).
5. نکته: ستون `sku` همان `supplier_code` کالا در دیجی‌کالا است (تنظیم `COST_SKU_FIELD`)؛ اگر نخواستید از `variant_id` استفاده کنید.

## مرحله ۳: تعیین حاشیه سود
در ترمینال (یا با کمک برنامه‌نویس) مثلاً برای همه کالاها ۱۰٪ سود و حداقل ۵۰٬۰۰۰ تومان:
```bash
docker compose exec worker python -m sudyar set-floor --scope global --margin-pct 10 --min-profit 50000
```
قانون برای یک برند/دسته/کالای خاص (اولویت: کالا ← برند ← دسته ← همه):
```bash
docker compose exec worker python -m sudyar set-floor --scope variant --key 12345 --margin-pct 15
```
«کف دستی» (وقتی قیمت خرید ندارید): `--manual-toman 800000` یا `--manual-pct 90` (٪ قیمت فعلی).

## مرحله ۴: گزارش
دو بار کلیک روی `5-floor-report.bat`. نشان می‌دهد:
- کالاهایی که با قیمت فعلی سود صفر یا منفی دارند (بر اساس آمار فروش واقعی؛ بخش ۳ب)
- کالاهایی که قیمت برنده باکس خرید از کف شما پایین‌تر است
- تعداد کالاها به تفکیک وضعیت (ok / needs_cost / needs_fees / needs_unit / no_rule)

## رادار و کف قیمت
وقتی رادار باکس خرید را از دست دادن کالایی ببیند، پیام فارسی یکی از این‌ها را می‌گوید: «می‌توان بالاتر از کف قیمت برنده شد» یا «برای برنده شدن باید پایین‌تر از کف قیمت رفت» یا «قیمت خرید ثبت نشده». پیام‌ها هنوز آزمایشی (DRY-RUN) هستند مگر `NOTIFY_ENABLED=true` بنویسید.

## امنیت داکر (برای اطلاع)
برنامه با کاربر معمولی (نه مدیر) اجرا می‌شود، فایل‌های داخل کانتینر فقط‌خواندنی هستند (فقط پوشه `data` قابل نوشتن است)، حافظه و پردازنده محدود است، و هیچ رمز یا توکنی داخل تصویر داکر ذخیره نمی‌شود (فقط از `.env` هنگام اجرا خوانده می‌شود).

## بخش ۳ این کارها را **نمی‌کند**
- هیچ قیمت، موجودی یا تخفیفی را در دیجی‌کالا تغییر نمی‌دهد (فقط می‌خواند و پیشنهاد می‌دهد).
- کمیسیون و هزینه‌های دیجی‌کالا را حدس نمی‌زند؛ تا آدرس‌های رسمی در `.env` تنظیم نشود، کفی محاسبه نمی‌شود.
- قیمت رقبا را تحلیل نمی‌کند و قیمت جدید خودکار نمی‌گذارد.
- رابط گرافیکی (وب) ندارد؛ فقط فایل‌های دو‌بار‌کلیک و دستورهای ترمینال.
- هزینه‌های ارسال/مالیات/تبلیغات/مرجوعی/بسته‌بندی را خودتان باید بنویسید.

# بخش ۳ب: کمیسیون و آمار فروش واقعی دیجی‌کالا

از این بخش به بعد، کف قیمت با **اطلاعات واقعی دیجی‌کالا** حساب می‌شود. باز هم فقط خواندن است و هیچ قیمتی تغییر نمی‌کند.

## توکن شما این دسترسی‌ها را لازم دارد
دقیقاً این چهار دسترسی (جدول کامل در بخش ۳ج):
- **variant**: برای خواندن کالاها و قیمت پیشنهادی باکس خرید (winning-price)
- **commission**: برای خواندن کمیسیون‌ها
- **insight**: برای خواندن آمار فروش
- **order**: برای خواندن سفارش‌ها و ساختن فروش واقعی هر روز (بخش ۴ج)

اگر پیام «check the Self Token scopes» دیدید، یعنی توکن شما یکی از این دسترسی‌ها را ندارد؛ در پنل فروشنده توکن را با دسترسی کامل بسازید.

## واحد قیمت
قیمت‌های دیجی‌کالا **ریال** هستند (`DIGIKALA_PRICE_UNIT=rial` که از قبل در `.env.example` است). برنامه برای محاسبه کف قیمت، ریال را به **تومان** تبدیل می‌کند (تقسیم بر ۱۰) و در پیام‌ها همه چیز را **به تومان** نشان می‌دهد. قیمت خرید و حداقل سود هم به **تومان** وارد می‌شوند.

## مرحله ۱: خواندن کمیسیون و فروش
دو بار کلیک روی **`2b-sync-fees-sales.bat`**. (یا در ترمینال:)
```bash
docker compose exec worker python -m sudyar sync-fees
docker compose exec worker python -m sudyar sales-sync --range last_30_days
```
- کمیسیون‌ها حداکثر هر ۲۴ ساعت یک بار دوباره خوانده می‌شوند.
- بازه فروش یکی از `last_7_days`، `last_14_days`، `last_30_days` است. اگر کمتر از ۲۴ ساعت پیش خوانده باشید، از اطلاعات ذخیره‌شده استفاده می‌شود (برای خواندن دوباره `--force` بنویسید).
- فروش برای هر **محصول** است؛ همه تنوع‌های یک محصول عدد فروش یکسان نشان می‌دهند.

## کمیسیون چطور انتخاب می‌شود؟
- بر اساس **دسته‌بندی** کالا (`category_id`).
- دیجی‌کالا در لیست کالاها **برند** نمی‌دهد. اگر یک دسته چند برند با کمیسیون متفاوت دارد و برند کالا را مشخص نکرده‌اید، برنامه **بیشترین کمیسیون** را برمی‌دارد (محافظه‌کارانه) و در گزارش و پیام می‌نویسد «بیشترین مقدار برندهای این دسته». 
- اگر می‌خواهید دقیق‌تر شود، برند یک کالا را دستی مشخص کنید:
```bash
docker compose exec worker python -m sudyar list-brands 101
docker compose exec worker python -m sudyar set-brand --variant 12345 --brand-id 5
```
(به‌جای `101` شماره دسته و به‌جای `5` شماره برند از لیست.) بعد از آن می‌توانید برای آن برند قانون جدا هم بگذارید: `set-floor --scope brand --key 5 ...`.
- دو مقدار `extra_commission` و `return_free_commission` در داکیومنت دیجی‌کالا **معنی‌شان مشخص نیست**، پس به‌طور پیش‌فرض در کف قیمت **حساب نمی‌شوند**. اگر معنی‌شان را فهمیدید، در `.env` مقدار `FLOOR_INCLUDE_EXTRA_COMMISSION=true` یا `FLOOR_INCLUDE_RETURN_FREE_COMMISSION=true` بگذارید. گزارش همیشه می‌گوید این‌ها حساب شده‌اند یا نه.

## هزینه‌هایی که دیجی‌کالا نمی‌دهد (باید خودتان بنویسید)
برای این‌ها هیچ آدرسی در دیجی‌کالا پیدا نشد، پس مقدارشان را **خودتان** مشخص می‌کنید؛ تا وقتی ننویسید، در محاسبه **صفر** حساب می‌شوند و گزارش و پیام آن را صریح می‌گویند (تا فریب نخورید):
پردازش/ارسال (fulfillment)، مالیات (tax)، سهم تبلیغات (ad-share)، ذخیره مرجوعی (return-reserve)، بسته‌بندی (packaging).

هر کدام را می‌توانید **درصد از قیمت** (`-pct`) یا **مبلغ ثابت به تومان** (`-toman`) بنویسید. مثال برای همه کالاها (۹٪ مالیات، ۲٪ تبلیغات، ۱۵٬۰۰۰ تومان بسته‌بندی):
```bash
docker compose exec worker python -m sudyar set-floor --scope global --tax-pct 9 --ad-share-pct 2 --packaging-toman 15000
```
برای یک دسته خاص (اولویت با دسته است):
```bash
docker compose exec worker python -m sudyar set-floor --scope category --key 101 --fulfillment-toman 30000
```

## قیمت خرید و شناسه کالا در اکسل
ستون `sku` در فایل اکسل، همان **`supplier_code`** (کد تأمین‌کننده) کالا در دیجی‌کالا است. اگر نخواستید، از ستون `variant_id` استفاده کنید.

## گزارش جدید
`5-floor-report.bat` حالا با **فروش واقعی** کار می‌کند:
- کالاهایی که **می‌فروشند ولی سود صفر یا منفی دارند**، به ترتیب بیشترین تعداد فروش (`net_item_sold`)
- کالاهایی که قیمت برنده باکس خرید از کف شما پایین‌تر است
- فهرست «هزینه‌هایی که حساب شده» و «هزینه‌هایی که تنظیم نشده»
- یادداشت درباره `extra_commission` و `return_free_commission` (معنی نامشخص)

## بخش ۳ب این کارها را **نمی‌کند**
- برای محاسبه کمیسیون، «ماشین‌حساب قیمت» دیجی‌کالا را صدا نمی‌زند (چنین آدرسی در داکیومنت نیست).
- برند را خودکار تشخیص نمی‌دهد.
- هزینه‌های ارسال، مالیات، تبلیغات، مرجوعی و بسته‌بندی را حدس نمی‌زند.
- معنی `extra_commission` و `return_free_commission` را حدس نمی‌زند.
- فروش هر **تنوع** را جدا نمی‌داند (فروش فقط برای هر محصول است).
- هیچ قیمت یا موجودی را در دیجی‌کالا تغییر نمی‌دهد.

# بخش ۳ج: اصلاحات امنیتی و دسترسی‌های توکن

## توکن (Self Token) چه دسترسی‌هایی لازم دارد؟
توکن را در پنل فروشنده **فقط با دسترسی «خواندن» (read-only)** و دقیقاً برای این چهار دسترسی بسازید. هیچ دسترسی «نوشتن» لازم نیست و برنامه هرگز چیزی در دیجی‌کالا تغییر نمی‌دهد:

| دسترسی (scope) | چه چیزی را می‌خواند |
|---|---|
| `variant` | `GET /open-api/v1/variants` (فهرست کالاهای شما) و `GET /open-api/v1/pricing/buybox/price-suggestion/winning-price` (قیمت پیشنهادی برای باکس خرید؛ دسترسی جدا به نام «pricing/buybox» وجود ندارد) |
| `commission` | `GET /open-api/v1/commissions/` (کمیسیون‌ها) |
| `insight` | `GET /open-api/v1/insight/sales-reports` (آمار فروش) |
| `order` | `GET /open-api/v1/orders/history` (و `GET /open-api/v1/orders`) برای فروش واقعی هر روز |

این چهار، دسترسی‌های رسمی Service Hub هستند. **هشدار:** در دسترسی `order` دیجی‌کالا یک متد `DELETE /open-api/v1/orders/{order_item_id}` هم دارد (لغو سفارش). برنامه‌ی ما فقط GET می‌زند و آن را **هرگز** صدا نمی‌زند (کد و تست آن را قفل کرده‌اند)، ولی خود توکن با این دسترسی از نظر دیجی‌کالا اجازه‌ی لغو دارد؛ توکن را جای دیگری استفاده یا منتشر نکنید. دستور `check-config` همین فهرست را چاپ می‌کند.

## چه چیزهایی در این نسخه سخت‌گیرانه‌تر شد
- **کف دستی** همیشه بزرگ‌تر از صفر است و اگر قیمت خرید را دارید، هرگز پایین‌تر از قیمت خرید نمی‌رود.
- **کمیسیون:** اگر در یک دسته فقط یک برند ثبت شده باشد، گزارش می‌نویسد «فقط نرخ همان یک برند فرض شد» (`fee_assumed_single_brand`). اگر بعضی ردیف‌های یک دسته نامعتبر باشند، برای آن دسته کفی محاسبه نمی‌شود (چون بیشترین کمیسیون معلوم نیست).
- اگر تعداد ردیف‌های کمیسیون نسبت به دفعه قبل **بیش از ۳۰٪** کم شود، `sync-fees` رد می‌شود و ردیف‌های قبلی می‌مانند (برای پذیرفتن عمدی: `sync-fees --force`).
- اگر کمیسیون‌ها بیش از **۳ روز** به‌روز نشوند (مثلاً چون دیجی‌کالا جواب نمی‌دهد)، وضعیت کف قیمت `needs_fees` می‌شود. مقدار با `FEES_MAX_STALE_DAYS` تغییر می‌کند.
- عددهای غیرمنطقی (NaN، بی‌نهایت، خیلی بزرگ، منفی) در `set-floor` و `.env` پذیرفته نمی‌شوند. اگر یک کالا در گزارش خطا بدهد، فقط همان کالا رد می‌شود و گزارش ادامه پیدا می‌کند.
- `DIGIKALA_BASE_URL` باید با `https://` شروع شود و آدرس‌های API باید با `/` شروع شوند.
- پیام خطا فقط نوع و یک کد کوتاه (مثل `HTTP-403`) را نشان می‌دهد. برای جزئیات: در `.env` بنویسید `SUDYAR_DEBUG=1` (رمزها همیشه پنهان می‌شوند).
- آدرس «بله» فقط اگر در `BALE_ALLOWED_HOSTS` باشد پذیرفته می‌شود (پیش‌فرض `tapi.bale.ai`؛ تأیید نشده، با مستندات بله چک کنید).
- اگر فایل `.env` برای کاربران دیگر کامپیوتر خواندنی باشد، `check-config` هشدار می‌دهد (در لینوکس/مک: `chmod 600 .env`).

# بخش ۳ه: ردیف کمیسیون بدون دسته (توقف ایمن)

اگر در داده‌های کمیسیون دیجی‌کالا **حتی یک ردیف بدون دسته (category_id)** باشد، برنامه نمی‌تواند بداند آن ردیف مال کدام دسته است؛ پس به هیچ‌کدام از کمیسیون‌ها اعتماد نمی‌کند:
- وضعیت **همه** کف‌ها `needs_fees` می‌شود (نه ok و نه صفر). کف دستی هم این را دور نمی‌زند.
- گزارش (`floor-report`)، `check-config` و `sync-fees` این پیام را نشان می‌دهند: «یک ردیف کمیسیون بدون دسته پیدا شد؛ تا اصلاح نشود هیچ کفی نمایش داده نمی‌شود».
- وقتی دیجی‌کالا ردیف را اصلاح کرد، یک بار `sync-fees` بزنید؛ کف‌ها خودکار برمی‌گردند.
- همین مسیر ایمن وقتی هم کار می‌کند که ردیف‌های نامعتبر از سقف مجاز بیشتر شوند.

# بخش ۴الف: صفحه‌ی وب فارسی

یک صفحه‌ی ساده‌ی فارسی برای دیدن وضعیت، بدون ترمینال. **فقط می‌خواند**؛ هیچ چیزی در دیجی‌کالا تغییر نمی‌کند و حتی به دیجی‌کالا وصل هم نمی‌شود (فقط اطلاعاتی را نشان می‌دهد که قبلاً در پایگاه داده‌ی خودتان ذخیره شده).

## راه‌اندازی (۳ مرحله، ویندوز)
1. **Docker Desktop** را باز کنید و صبر کنید تا آماده شود.
2. روی فایل **`8-web.bat`** دو بار کلیک کنید (بار اول چند دقیقه طول می‌کشد).
3. مرورگر خودش باز می‌شود؛ اگر باز نشد، این آدرس را بزنید: **http://127.0.0.1:8080**

برای نصب مثل یک برنامه (روی همان کامپیوتر): در Chrome یا Edge روی نشانه‌ی «نصب» در نوار آدرس بزنید.

## چهار صفحه (نوار پایین)
- **امروز:** حداکثر ۳ کار مهم (باخت بای‌باکس و علتش، اطلاعات ناقص، داده‌ی قدیمی). «سود خالص دیروز» همیشه «نامشخص» است چون دیجی‌کالا فروش روزانه نمی‌دهد؛ به‌جایش یک **تخمین ۷ روز اخیر** (فروش × سود هر عدد با قیمت امروز) و دلیل کنار گذاشتن بعضی محصول‌ها نوشته می‌شود.
- **رادار:** کالاها در سه گروه داغ / گرم / آرام، وضعیت باکس خرید، زمان آخرین بررسی و علت باخت.
- **کف قیمت:** کف هر کالا و منبع هر عدد (قیمت خرید، کمیسیون، هزینه‌ها، قانون سود). اگر عددی نباشد، همان را با اسم می‌گوید («قیمت خرید ثبت نشده») و حدس نمی‌زند.
- **تنظیمات:** وضعیت اتصال (بدون نمایش توکن)، ساعت گزارش صبح (پیش‌فرض ۸)، ساعت آرام (پیش‌فرض ۲۳ تا ۷) و ارسال واقعی هشدار (پیش‌فرض: آزمایشی).

## امنیت
- صفحه فقط روی **همین کامپیوتر** باز می‌شود (`127.0.0.1`).
- اگر خواستید از کامپیوتر دیگر باز شود، حتماً در `.env` مقدار `WEB_PASSWORD=` را پر کنید؛ بدون رمز، برنامه اجازه‌ی شروع نمی‌دهد.
- ساعت‌هایی که در صفحه ذخیره می‌کنید روی هشدارهای رادار اثر می‌گذارد. «ارسال واقعی» فقط وقتی کار می‌کند که توکن بله یا تلگرام در `.env` باشد.

## این بخش **نمی‌کند**
- قیمت خرید وارد نمی‌کند (بخش ۴ب).
- گزارش صبح را نمی‌فرستد: ساعتش ذخیره می‌شود اما ارسال خودکار هنوز ساخته نشده.
- روی گوشی از راه دور باز نمی‌شود (نیاز به رمز و HTTPS دارد و در این بخش نیست).

# بخش ۴ج: سود واقعی دیروز از سفارش‌های دیجی‌کالا

صفحه‌ی «امروز» حالا **سود واقعی دیروز** را نشان می‌دهد (روز تهران)، نه تخمین ۷ روزه. تخمین قبلی فقط وقتی می‌آید که دسترسی `order` نباشد یا هنوز سفارشی خوانده نشده باشد، و با برچسب «تخمین جایگزین» جدا شده است.

```bash
python -m sudyar orders-sync              # سه روز کامل اخیر (ORDERS_DEFAULT_DAYS)، تا دیروز
python -m sudyar orders-sync --days 7 --force
python -m sudyar orders-show              # فروش ذخیره‌شده‌ی دیروز (فقط از پایگاه داده، بدون تماس با دیجی‌کالا)
```

دوبار کلیک روی `9-orders-sync.bat`: فروش دیروز را (فقط‌خواندنی) می‌خواند و فهرست تعداد و قیمت هر کالا را نشان می‌دهد تا با پنل مقایسه کنید.

- فقط `GET /open-api/v1/orders/history` (و `GET /open-api/v1/orders`) خوانده می‌شود؛ سقف ۳۰ خواندن در ۳۰ ثانیه رعایت می‌شود و صفحه‌ها یکی‌یکی خوانده می‌شوند.
- برای هر روز و هر کالا فقط این‌ها ذخیره می‌شود: شناسه‌ی تنوع، تعداد، قیمت فروش واحد، تاریخ. **نام، تلفن، آدرس، شماره‌ی سفارش یا ارسال ذخیره نمی‌شود.**
- سفارش لغوشده حساب نمی‌شود؛ مرجوعی منفی حساب می‌شود (در روز ثبت سفارش اصلی).
- اگر تعداد صفحه‌ها از `ORDERS_MAX_PAGES` بیشتر شود، آن روز ذخیره **نمی‌شود** (عدد ناقص نشان داده نمی‌شود).
- سود هر عدد با همان قیمت خرید، کمیسیون و هزینه‌های دستی کف قیمت حساب می‌شود، ولی با **قیمت فروش واقعی**. تنوعی که قیمت خرید یا کمیسیون ندارد کنار گذاشته می‌شود و تعدادش نوشته می‌شود.

## فرض‌ها: کدام تأیید شد، کدام نه (بررسی روی پنل فروشنده‌ی اسفورتی، ۲۴ آبان ۱۴۰۵)
1. ✅ **واحد قیمت ریال است.** پنل همان عدد `unit_price` را با برچسب «ریال» نشان می‌دهد (مثلاً ۱۹٬۲۱۳٬۲۰۰ ریال).
2. ✅ **شکل پاسخ:** `data.items` و `data.pager` با همین نام فیلدها (`product_variant_id`، `quantity`، `unit_price`، `unit_discount`، `total_price`، `order_created_at`).
3. ✅ **تاریخ** به شکل `2026-11-15T00:59:02+03:30` (با ساعت تهران) می‌آید و درست خوانده می‌شود.
4. ✅ **`order_status`** یک شیء است (`processed`، `returned`، `canceled`). خط لغوشده حساب نمی‌شود و خط مرجوعی فقط یک بار (از درخواست مرجوعی) کم می‌شود.
5. ✅ `total_price = unit_price × quantity` در همه‌ی ۵۵۰ سفارش بررسی‌شده.
6. ⏳ **تخفیف:** در ۵۵۰ سفارش اخیر هیچ تخفیف فروشنده‌ای نبود، پس `ORDERS_DISCOUNT_MODE` فعلاً اثری ندارد. با اولین سفارش تخفیف‌دار بررسی شود.
7. ⏳ `seller_voucher_amount` کم نمی‌شود (در این سفارش‌ها همیشه صفر بود).

بررسی از API داخلی پنل (`/api/v2/orders-history`) با همان نشست مرورگر فروشنده انجام شد؛ همان نام فیلدهای Open API را دارد. برای تأیید: بعد از اولین `orders-sync` واقعی، یک سفارش شناخته‌شده را با پنل مقایسه کنید.

# بخش ۴ب: ثبت قیمت خرید در صفحه‌ی وب

صفحه‌ی **«قیمت خرید»** (تب پنجم) برای وارد کردن قیمت خرید کالاهاست. **اختیاری است و هیچ‌جا اجباری نمی‌شود.** کالایی که قیمت خرید ندارد مثل قبل با کف دستی (عدد یا درصد) کار می‌کند و هیچ قیمتی حدس زده نمی‌شود. همه‌چیز فقط در پایگاه داده‌ی خودتان ذخیره می‌شود؛ **هیچ‌چیز به دیجی‌کالا فرستاده نمی‌شود.**

- **ویرایش تکی:** در جدول، قیمت خرید را **به تومان** بنویسید (ارقام فارسی و جداکننده‌ی هزارگان مجازند) و «ذخیره» را بزنید. «پاک کردن» قیمت خرید آن کالا را برمی‌دارد. جست‌وجو با نام یا شناسه‌ی کالا.
- **فایل اکسل/CSV:** همان قالب و همان بررسی دستور `import-costs` (ستون `buy_cost` و یکی از `variant_id` یا `sku`). اول **پیش‌نمایش** می‌بینید: چند ردیف درست است، کدام ردیف‌ها رد شده و چرا (به فارسی)، و کدام قیمت‌ها از قدیم به جدید عوض می‌شوند. **فقط با دکمه‌ی «تأیید و ذخیره»** چیزی ذخیره می‌شود؛ پیش‌نمایش تا ۱۵ دقیقه معتبر است و فقط برای همان ورود.
- **محدودیت و ایمنی:** فقط `.xlsx` و `.csv`، حداکثر ۲ مگابایت و ۵۰۰۰ ردیف. فرمول اجرا نمی‌شود (فقط مقدار خوانده می‌شود)، فایل با ماکرو و فایل‌های زیپِ بیش‌ازحد بزرگ رد می‌شوند و نام فایل شما هیچ‌جا روی دیسک استفاده نمی‌شود.
- **سابقه (audit):** هر تغییر یک خط می‌نویسد: کالا، قیمت قبلی، قیمت جدید، منبع (`manual` دستی / `file` فایل) و زمان. ۲۰ تغییر آخر در همین صفحه دیده می‌شود. ایمپورت با دستور `import-costs` هم همین سابقه را می‌نویسد.
- **وب فقط این جدول‌ها را می‌نویسد:** `variant_costs`، `cost_audit` و `app_settings` (فرم هشدار). تست‌ها این را قفل کرده‌اند.
- جدول تازه `cost_audit` با مایگریشن `0009` ساخته می‌شود (با `docker compose up` خودکار اجرا می‌شود).

**فرض تأییدنشده:** ورودی‌ها همیشه **تومان** هستند (مثل `import-costs`)؛ اگر قیمت خرید را به ریال نوشتید، کف قیمت ۱۰ برابر می‌شود.


# آماده‌سازی برای سرور (بعداً)

روی کامپیوتر خودتان لازم نیست کاری بکنید. هنگام بردن روی سرور:
- `WEB_HTTPS_ONLY_COOKIE=1` تا کوکی ورود فقط روی HTTPS فرستاده شود. اگر صفحه از بیرون باز باشد و این تنظیم نباشد، برنامه هشدار می‌دهد.
- `WEB_TRUSTED_PROXIES` = آی‌پی پراکسی (مثلاً nginx) تا محدودیت رمز اشتباه برای هر بازدیدکننده جدا شمرده شود.
- برنامه فقط آدرس‌های خواندنی تنظیم‌شده‌ی دیجی‌کالا را صدا می‌زند؛ هر آدرس دیگری قبل از ارسال رد می‌شود.

# بخش ۵الف: نصب روی سرور (یک دستور)

برای وقتی که سودیار از کامپیوتر شما به سرور می‌رود. روی کامپیوتر خودتان هیچ‌چیز عوض نمی‌شود.

**چه لازم است:** یک سرور اوبونتو ۲۲.۰۴ یا ۲۴.۰۴ (پیشنهاد: ۲ هسته، ۴ گیگ رم، ۴۰ گیگ دیسک) و دامنه‌ای که رکورد `A` آن به آی‌پی سرور اشاره کند (مثلاً `app.sudyarapp.ir`).

**نصب:** پوشه‌ی سودیار را روی سرور بگذارید و در همان پوشه بزنید:

```bash
sudo bash deploy/install.sh
```

اسکریپت این کارها را خودش انجام می‌دهد: نصب Docker، بستن همه‌ی درگاه‌ها جز SSH و ۸۰ و ۴۴۳، ساخت `.env` با رمزهای تصادفی، پرسیدن دامنه، ایمیل، رمز صفحه‌ی وب و توکن دیجی‌کالا (تایپ پنهان؛ هیچ‌جا چاپ نمی‌شود) و روشن کردن برنامه. اگر دوباره اجرا شود، مقدارهای قبلی `.env` را عوض نمی‌کند.

- **HTTPS خودکار:** Caddy گواهی رایگان می‌گیرد و تمدید می‌کند. صفحه فقط با رمز باز می‌شود؛ برنامه در حالت سرور بدون رمز ۱۲ حرفی و کلید کوکی اصلاً روشن نمی‌شود.
- **پایگاه داده** از بیرون در دسترس نیست. Caddy هیچ توکن و رمزی نمی‌بیند.
- **پشتیبان:** هر روز یک فایل در پوشه‌ی `backups` (۱۴ روز نگه داشته می‌شود). برگرداندن یک پشتیبان:
  `docker compose -f docker-compose.yml -f deploy/docker-compose.server.yml exec -T backup pg_restore --clean --if-exists -d sudyar < backups/sudyar-YYYY-MM-DD.dump`
- **به‌روزرسانی:** `git pull` و سپس همان خط `up -d --build` که اسکریپت در پایان نشان می‌دهد.

**مخصوص سرور ایرانی (تأییدنشده):**
- Docker Hub بسیاری از آی‌پی‌های ایران را رد می‌کند. اگر رد کرد، اسکریپت پیشنهاد آینه‌ی آروان (`docker.arvancloud.ir`) را می‌دهد.
- تلگرام از سرور ایرانی معمولاً باز نمی‌شود؛ روی سرور ایرانی هشدار را با **بله** بفرستید.
- گرفتن گواهی HTTPS به دسترسی سرور به Let's Encrypt یا ZeroSSL بستگی دارد؛ در اولین نصب بررسی شود.

# بخش ۵ب: اتصال فروشنده از راه سرویس‌هاب (OAuth)

بعد از اینکه دیجی‌کالا سودیار را در سرویس‌هاب تأیید کند، فروشنده دیگر لازم نیست Self Token بسازد؛ فقط در صفحه‌ی **تنظیمات ← اتصال به دیجی‌کالا** دکمه را می‌زند، در پنل دیجی‌کالا «تأیید» می‌کند و برمی‌گردد. منبع: راهنمای «احراز هویت فروشنده (OAuth 2.0)» در آکادمی سرویس‌هاب.

- **فقط خواندن:** دسترسی‌ها `variant.read order.read commission insight` است. هر دسترسی که بتواند چیزی بنویسد (بدون `.read`) رد می‌شود و اتصال انجام نمی‌شود.
- **توکن‌ها رمزگذاری‌شده** در پایگاه داده نگه داشته می‌شوند (کلید `SUDYAR_TOKEN_KEY`) و هیچ‌جا نمایش یا لاگ نمی‌شوند. توکن ۲ ساعته خودکار تمدید می‌شود؛ اعتبار کلی یک سال است.
- تنها تماس‌های نوشتنی این بخش دو آدرس `POST /open-api/v1/auth/token` و `POST /open-api/v1/auth/refresh-token` است (گرفتن و تمدید توکن). خواندن داده‌ها مثل قبل فقط با GET است.
- تا وقتی `DIGIKALA_SELF_TOKEN` پر است، همان Self Token استفاده می‌شود و چیزی عوض نمی‌شود.

**برای ثبت اپ در سرویس‌هاب (یک بار، روی سرور):**

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.server.yml exec web python -m sudyar oauth-keygen
```

کلید خصوصی در `data/secrets` ساخته می‌شود (هرگز بازنویسی نمی‌شود؛ از آن پشتیبان بگیرید) و **کلید عمومی** چاپ می‌شود تا در فرم ثبت (`public_key`) بگذارید. بقیه‌ی فرم: `host` = دامنه، `redirect_url` = `https://<دامنه>/oauth/callback`، `required_scopes` = همان چهار دسترسی بالا. بعد از تأیید، `client_code` را در `.env` بگذارید (`SERVICEHUB_CLIENT_CODE=`) و `DIGIKALA_SELF_TOKEN` را خالی کنید. وضعیت: `python -m sudyar oauth-status`.

**تأییدنشده:** اینکه `commission` و `insight` پسوند `.read` هم می‌پذیرند یا نه؛ و اینکه پاسخ توکن دقیقاً همان شکل راهنما را دارد. با اولین اتصال واقعی بررسی شود.
